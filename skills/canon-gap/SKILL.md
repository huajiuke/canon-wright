# Canon Gap

读完一章草稿，把作者**写作中暴露的知识缺口**抽出来交作者选定，然后只做一件事：写进缺口台账。

- 输入：一章草稿，以及已有台账。
- 输出：候选缺口 + 每个缺口的 3–5 个互斥方向；作者选定后落入台账。
- 不输出：书单、资料摘要、正文修改建议。

## 触发时机

只在**章末或作者主动召唤**时运行。作者正在写作时不要介入——写作时不打扰是产品原则，不是偏好。作者中途说「这里我拿不准」时，只回一句「记下了，章末一起整理」，不要当场展开。

## 定位小说库

从当前目录向上找 `.canon/config.yml` 作为库根，路径从 `paths` 段读。找不到就问作者库在哪，不要猜。

## 流程

### 1. 读稿

读作者指定的章；未指定则读 `manuscript/` 下最近修改的一章。同时读已有台账，避免重复登记。

### 2. 抽候选缺口

逐段问：**这里的写作意图是否依赖作者当前不具备的具体知识？**

「不查也能硬写、只是查了更好」不算缺口。缺口是**不查就会写错或写空**的地方。

每条候选给四属性：

- `need`：需要什么，写成一句可检索的话
- `type`：`fact`（会过期）｜`craft`（写法，几乎不过期）｜`motif`（影响整本结构）
- `why`：为什么现在需要，**挂到具体章与具体段落**，引一句原文定位
- `granularity` 与 `deadline_chapter`：读多少能闭合，以及最晚哪章要用

宁少勿滥，一章 3–7 条足够。抽不出 3 条就如实说这一章没有实质缺口，不要凑数。

### 3. 给互斥方向

对每条候选给 3–5 个**互斥**方向。互斥的意思是：选定一个即排除其余——它们是对「补什么」的不同选择，不是同一个答案的不同来源。

```
缺口：明代私铸钱的法禁与实际流通差异
why：ch-007 沈砚在市集用假钱试探，需要知道当时钱法如何执行

互斥方向（选一个即排除其余）：
  A 法制史 — 《大明会典》的钱法条目，要法条原文
  B 经济史 — 明代货币流通研究，要实际流通的量化描述
  C 笔记小说 — 明人笔记里的市井用钱记载，要能直接入文的细节
  D 实物 — 明代钱币图录，要形制、重量、成色
```

三条禁令：

- 不在方向里夹带书单或链接，检索不属于这一步。
- 不替作者排序，不标注推荐。
- 不因为自己觉得某个方向不重要就不列出来。

### 4. 等作者选定

一次交付全部候选，请作者逐条选方向或标「放弃」。

**不要替作者选，也不要默认全选。** 选什么本身是创作行为，不能让渡给模型。作者标放弃的按 `abandoned` 落台账并写明理由；作者没表态的不落台账。

### 5. 落台账

追加到 `gaps/inbox.md`：id 取现有最大编号 +1，格式 `G-NNN`；追加 `## G-NNN` 小节与字段列表。若需求与已有 `open` 条目重复，合并而不是新增。

字段定义、状态流转与示例见 `references/gap-ledger.md`。

## 硬规则

- `why` 写不出「挂在哪章哪段」→ 不入台账。
- `granularity` 超过 30 分钟阅读量 → 先切碎到章节级再入台账，不要原样登记整本书。
- 台账只增不改：闭合与放弃是改 `status`，不删条目、不重写历史。
- 不臆造知识来填缺口。你只负责指出缺口在哪，不负责补上它。
- 不改正文。正文是作者的。
